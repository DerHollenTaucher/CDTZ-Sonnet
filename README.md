# WallCity 围墙之城

一个第一人称 3D 答题冒险游戏（Three.js + WebGL），由原来那份半成品的原型重构而来。
地图就是你高中那座校园（你自己做的那套模型），**不分区域**，三个学科的“怪物”随机散在
校园各处 —— 可能在楼里、走廊上，也可能在院子里。

走到它们身边会弹出题目，**答对**怪物消散、得分；**答错**就会看到该学科的“惩罚”——
惩罚文字和图片延续了原型里的那份恶趣味（十套卷子、背《滕王阁序》、五篇课文）。

```
W A S D / 方向键   移动            Shift   疾跑
空格              跳跃            Esc     暂停（释放鼠标）
M                 开关小地图      R       卡住时回到出生点
```

## 一、怎么运行

游戏用的是 ES Module，浏览器的安全策略**不允许**从 `file://` 直接打开模块脚本
（会报 `Cross origin requests are only supported for protocol schemes…`）。
所以必须通过一个小小的本地服务器打开，两种方式任选：

### 方式 1：一键启动（推荐）

双击 **`启动游戏.bat`**。它会：

1. 检查有没有 Python（没有会提示去装）；
2. 用 Python 起一个本地静态服务器（`tools/serve.py`）；
3. 自动用默认浏览器打开 `http://127.0.0.1:8080/index.html`。

关掉那个黑窗口就等于关掉服务器。

### 方式 2：手动

```bat
cd /d E:\WallCity
python tools\serve.py                :: 默认 8080，端口被占用会自动往后找
python tools\serve.py --port 9000    :: 指定端口
python tools\serve.py --no-browser   :: 不自动开浏览器
```

用 VS Code 的 **Live Server** 插件打开 `index.html` 也可以。
（Node 环境的话 `npx serve` 之类同样可以。）

### 完全离线

`vendor/` 里已经放好了 three.js 0.160.0 和 three-mesh-bvh 0.7.8，运行时**不需要联网**。
（`OBJLoader.js` / `MTLLoader.js` 是留着备用 的：万一想回退成直接读 OBJ 的写法，
不用再下载；游戏本身现在只用 `GLTFLoader`。）
如果只想恢复成原型的 CDN 写法，把 `index.html` 里的 importmap 换成：

```html
<script type="importmap">
{
  "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.160.0/build/three.module.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.160.0/examples/jsm/",
    "three-mesh-bvh": "https://cdn.jsdelivr.net/npm/three-mesh-bvh@0.7.8/build/index.module.js"
  }
}
</script>
```

## 二、玩法说明

* 开始游戏后点一下画面锁定鼠标；`Esc` 释放鼠标并暂停。
* **靠近**怪物（11 米内）会提示距离，怪物头顶的指示器会变红并开始追你。
* 进到 **3 米**以内弹出答题面板：输入答案，回车（或点“提交”）判定。
* 答对：怪物被击败，+100 分（越快答题加成分越高），回到城里继续。
* 答错：进入“惩罚”界面，会显示正确答案，点“再来一局”重开整局。
* 击败全部 6 只怪物 → 通关结算（得分 / 正确率 / 用时）。
* 右下角小地图：彩色方块是三个街区，亮点是怪物（变红说明它发现你了）。
* 设置里的鼠标灵敏度 / FOV / 画质 / 音效 / 小地图 / FPS 都会记在 localStorage。

题目难度：数学题是程序生成的（所以答案永远正确），每击败 2 只难度提升一档；
语文是名句默写，英语是词汇语法，语文和英语题目在 20 多题的题库里轮换不重复。

**判题很宽容**：忽略大小写、空格、中英文标点、全角半角，语文答案繁简两种写法都接受。

## 三、关于你那 6 个模型（重要）

因为光看文件名看不出它们的关系，我写了个体素占用分析（`tools/analyze_tiles.py`），
把每个模型的顶点丢进 2 单位一格的网格里比较，结论是：
**这 6 个 OBJ 是同一座校园的 6 次导出。**

| 文件 | 地下 (y<-1) | 地面层 (-1~+5) | 楼上 (y>+5) | 与其他版本的关系 |
| --- | --- | --- | --- | --- |
| `CDTZ.obj` | **4814** | 7248 | 47083 | 与最新版只重合 25%、脚印完全在最新版之内 → **另一版（较早）设计** |
| `CDTZ1.obj` | 0 | 1811 | 51645 | 与 CDTZ2 重合 **99%**（同一次导出的两份），78% 落在最新版里 |
| `CDTZ2.obj` | 0 | 1799 | 56802 | 同上 |
| `CDTZ3.obj` | 0 | 1799 | 71087 | 80% 落在最新版里 |
| `CDTZ4.obj` | 0 | 2488 | 101198 | 94% 落在最新版里 |
| `CDTZ5.obj` | 0 | 3185 | **256139** | **最新最完整的一版**（向 z 延伸到 572） |

也就是：`CDTZ1 → CDTZ5` 是你一路把它做完的过程（越往后越大越细），
而**只有 `CDTZ.obj` 带地下部分**，它的地上部分是和最新版不同的另一版。

所以游戏默认这样处理（全部在 `js/config.js` 里可改，**不用动代码逻辑**）：

| 设置 | 默认 | 效果 |
| --- | --- | --- |
| `world.layout` | `'original'` | **用你导出时的原始坐标**（乘 0.45）拼成学校本来的样子；不再分数学区/语文区，也不再排网格 |
| `world.includeDrafts` | `false` | 只摆最新那一版 + 所有地下部分；早期版本先收起来，避免两版楼叠在一起互相穿插 |
| `world.includeUnderground` | `true` | y<0 的地下部分被单独切出来（`*_underground.glb`），就在地面之下，只有真的走下去才看得到 |

* 想看看「6 个版本全叠在一起」是什么效果 → 把 `includeDrafts` 改成 `true`；
* 只想要某一版作为校园 → 在 `tile_relationships.json` 里把它的 `role` 改成 `newest`，
  或者在 `world.layout` 保持 `'original'` 的前提下把别的地块 `role` 改成 `draft`；
* 想改回原来那种"排成一片城市"的玩法 → `world.layout = 'grid'`。

关于高度与地面（你提的第一点已按你说的实现）：

* 模型的**水平面就是地面**，所以世界坐标 `y = 0` 就是地面；
* 地面板放在 `y = -0.06`，既不会和模型自己的地面打架（z-fighting），
  又正好把 `y < 0` 的地下部分整个盖住；
* 切分规则是「三个顶点全部低于 0 才算地下」，所以从地下斜着伸出地面的坡道、
  挡土墙会留在校园本体里，地面上不会出现缺口。

关于"立体"（第二点）：

* 默认画质改成**精细（开阴影）**，因为这种手做模型有阴影才看得出体积和层次；
* 怪物不再被限制在"街面以下 9 米"，它们可以在 **16 米以内**的楼层/走廊/平台上活动
  （巡逻点是在校园里真实采样出来的可站立表面，不是贴地滑行）；
* 触发答题加了**高度差限制**（超过 12 米不算数），免得楼顶的怪物隔着楼层拉你答题；
  靠近提示里会写"楼上/楼下 N 米"；
* 小地图的底图是**碰撞体采样出来的俯视高度图**（越高越亮），能直接看出哪栋楼高、
  哪儿是院子 —— 这是它原来那四个彩色方块做不到的；
* 出生点是自动找的：从校园中心一圈圈往外找一处"脚下有面、头顶还有 2.2 米空间"的位置。

## 五、相比原来那份原型，改了什么

### 1. 修掉了这些“致命伤”（原型跑不起来的原因）

| 位置 | 原来的问题 | 现在 |
| --- | --- | --- |
| `index.html` | `scene.add(mainLight)` —— `mainLight` 从未定义，一执行就抛错 | 灯光在 `environment.js` 里统一创建 |
| `index.html` | `questionBank` 从未定义，答题必然报错 | 题库补全在 `questions.js` |
| `index.html` | `enemies.index0f(...)` 拼错 → 答对后崩溃 | 改为 `indexOf` 逻辑，且由 `enemies.js` 统一管理 |
| `index.html` | `setTimeOut` 拼错 → 答错后没反应 | 改为 `setTimeout` |
| `index.html` | `enemyTips` 写的是 `imag`，代码读的是 `.img` | 统一为 `penalty.images` |
| `index.html` | “生成 5 个敌人”的循环和 `animate()` 写在 `return` 之后 → 死代码，`animate()` 未定义 | 模块化，`main.js` 统一调度 |
| `index.html` | `restartGame()` / `checkAnswer()` 定义在 module 作用域，HTML 上 `onclick="restartGame()"` 找不到 → 按钮无效 | 全部改为 `addEventListener` |
| `game.js` | `letcollision = false`（少空格）+ 引用不存在的 `collision` 变量 | 删除，换成 `collision.js` 的真实实现 |
| `index.html` | CSS `font-sized` 拼错 | 修正 |
| 两者 | 贴图路径写的是 `textures/mathface`，文件根本不存在 | 指向 `assets/textures/face_*.jpg` |
| `game.js` | 每帧对 `scene.children` 递归 raycast 做碰撞，50 万面上必卡死 | BVH 加速射线，实测 < 1 ms/次 |
| `index.html` | 移动是“每帧乘 0.01”，帧率变了速度就变；跳跃写死回到 `y = 2` | 与帧率无关的加速 / 阻尼 + 重力 + 射线落地/顶头 |
| `index.html` | 地面只有 100×100，模型高度 130+，角色瞬间掉出地图 | 地面、雾、阴影范围按实际城市尺寸算 |

### 2. 性能与体积优化

| 项目 | 原型 | 现在 |
| --- | --- | --- |
| 模型格式 | 6 个 OBJ 文本，60.3 MB，浏览器里逐字解析 | 二进制 GLB，16.9 MB（**小 72%**），直接喂 GPU |
| 图片 | 5.08 MB（两张 2 MB+ 的照片） | 336 KB（**小 93%**） |
| 三角面 | 约 49.3 万 | 不变（几何未简化，只是换容器） |
| 碰撞 | 每帧全场景 raycast（不可用） | BVH，射线查询 O(log n) |
| 阴影 | 无 | 画质“精细”时可开，阴影相机跟随玩家只覆盖周围 55 米 |
| 依赖 | 每次运行都从 CDN 下载 three.js | 本地 `vendor/`，离线可玩 |
| 代码 | 两个互相矛盾的入口 + 死代码 | 10 个模块，职责清晰 |
| 地图组织 | （原型只加载了一个模型） | 6 个模型按**原始坐标**还原成整座校园，早期版本自动隐藏 |
| 地下部分 | 混在模型里、会被地形挡住 | 按 y=0 切成独立文件，地面板正好盖住它 |
| 小地图 | 无 | 碰撞体采样出来的**俯视高度图**（越高越亮）+ 敌人亮点 + 朝向旋转 |
| 立体感 | 无阴影、贴地移动 | 默认开阴影；怪物可在 16 米内的楼层活动；答题带高度差判断 |

> 注意：`tools/obj2glb.py` 会**丢掉 UV 坐标**（原来的 MTL 里没有任何贴图，UV 只会
> 白占 8 字节/顶点）。如果以后要给城市贴纹理，请把 `assemble()` 里的 UV 一起写进 GLB。

### 4. 画面与环境：渲染、季节、天气、时间

**渲染本身做了这些**（`js/weather.js` + `js/environment.js` + `js/main.js`）：

| 项目 | 说明 |
| --- | --- |
| 天空 | 换成 three 的**物理天空着色器**（`vendor/three/addons/objects/Sky.js`）：由太阳高度角、浑浊度、米氏散射驱动，日落和雾天的天空会自动变色，不再是一张固定渐变贴图 |
| 环境反射 | 每次切换环境都用 `PMREMGenerator` 把天空烘成环境贴图（`scene.environment`），于是**玻璃窗会反射天空**、湿地面会亮起来 |
| 材质分级 | 按材质名调参：窗户（`diffuse_Black`）→ 低粗糙度 + 金属度 + 反射，夜里**自发光变成亮着的窗**；墙面（`Plaster`）→ 粗糙漫反射，冬天会覆雪变浅；草地（`Plaster (1)`）→ 按季节换色 |
| 天空物品 | 程序化云层（fbm 噪声贴图的天穹，会缓慢飘）、星空（900 颗，只在夜里和晴天出现）、雨/雪粒子（共用一套 Points，数量靠 drawRange 调） |
| 真实太阳轨迹 | 太阳位置由 **纬度 + 日期 + 时刻** 用天文公式算出来（`js/solar.js`）：赤纬 δ≈23.44°·sin(360/365·(N−81))、高度角 sin h = sinφ·sinδ + cosφ·cosδ·cosω。所以冬天太阳真的低、影子真的长、昼长真的短 |
| 大气衰减 | 太阳越低穿过的空气越厚，用大气质量（air mass）算强度衰减，浑浊度/米氏散射随之变大，日出日落自然偏红 |
| 指数雾 + 空气透视 | 用 `FogExp2`（更像真实的霾），密度由能见度换算；雾的颜色还会**跟着视角方向变**：朝着太阳看偏暖、背对太阳看偏冷 |
| 月亮与月光 | 满月挂在太阳对面（真实的满月就是这样），夜里有一盏冷色平行光当月光，强度随月高与云量变化；月面是 512² 程序化贴图（月海 / 环形山 / 边缘变暗 / 地球反照），外面再加一圈**月晕**，靠近地平线时和太阳一样发红 |
| 日月的大小与眩光 | 真实的日面、月面都只有 0.5°，在屏幕上就是两个小光点，所以月面按 `world.sky.moonScale` 放大到约 1.8°，太阳则额外叠一层**眩光**：低太阳更大更红、正午小而白，云 / 雨 / 雪 / 雾都会把它压暗。这些观感参数都在 `js/config.js` 的 `world.sky` 里 |
| 夜空压暗 | three 的物理天空着色器没有真正的"夜天顶"，所以夜里额外套一层深蓝穹顶把天空压到该有的暗度，星星和月亮是后画的，不受影响 |
| 星空 | 900 颗星 + 一条 1600 点的银河带，只在夜里、云少的时候出现 |
| 云层受光 | 云的颜色跟着太阳走：正午白、日落暖橙、夜里冷灰；还会随风缓慢飘 |
| 光照与曝光 | 半球光/环境光分时段，雾色跟着天空走；曝光白天 0.8 / 夜里 0.42，阴雨天自动补一点（`exposure.adaptToWeather`），并夹在 min~max |
| 自适应分辨率 | 帧率长期低于 38 就自动把渲染分辨率降 15%（最低 60%），恢复后再升回去，并在 HUD 里提示一次 |
| 其他 | 载入完成后 `renderer.compile()` 预编译着色器（进游戏第一帧不卡）、阴影只在"精细"档开启、像素比上限 1.5 |

**季节 / 天气 / 时间**（右侧栏 `#weatherPanel`，也可以按快捷键）：

| 维度 | 选项 | 会改变什么 |
| --- | --- | --- |
| 季节 Season | 春 Spring / 夏 Summer / 秋 Autumn / 冬 Winter | 太阳高度角（冬天太阳更低、影子更长）、植被与地面颜色、积雪量、阳光冷暖 |
| 天气 Weather | 晴 Clear / 多云 Cloudy / 阴天 Overcast / 雾 Fog / 雨 Rain / 雪 Snow | 云量、天空浑浊度、能见度（雾的距离）、光照强度、雨雪粒子、地面干湿（湿地面会反光） |
| 时间 Time | 6 个预设（清晨/上午/正午/下午/傍晚/夜晚）+ 0~24 点滑杆 | 太阳方位与高度、天空颜色、亮度、夜里窗户发光与星空 |

快捷键：<kbd>H</kbd> 开关面板（打开时会自动放开鼠标，好让你点下拉框）、<kbd>F</kbd> 换天气、
<kbd>1</kbd>~<kbd>4</kbd> 换季节、<kbd>[</kbd> <kbd>]</kbd> 微调时间。
面板里还有「随机 Random」和「默认 Reset」。选择会记在 localStorage 里。
面板不长：只有季节 / 天气 / 时间 / 农历日常驻，**纬度、雾雨雪强度、真实农历、日月数据**
都收在「更多 ▼ More」按钮里，按一下才展开。

### 视角高度（觉得像矮人时用）

校园模型高 130 多米，第一人称站在街上确实容易觉得自己是矮人。所以眼睛高度可以随时调：

| 操作 | 作用 |
| --- | --- |
| <kbd>L</kbd> | 开关左上角的**视角面板**（打开时自动放开鼠标，好拖滑杆） |
| 面板滑杆 | 视角高度 1.2 ~ 61.7 米，拖完立刻生效 |
| <kbd>-</kbd> / <kbd>=</kbd> | 微调一步（默认 0.1 米）；**按住不放连续调**，按住 <kbd>Shift</kbd> 每步 0.6 米 |
| <kbd>0</kbd> | 回到人眼高度（1.7 米） |
| 「人眼 Eye」/「高一点 Higher」 | 面板里的两个快捷按钮 |

抬高的**只是眼睛**：脚底 = 眼睛 − eyeHeight − viewOffset，所以走路、贴地、走上台阶、跳跃、
掉出地图复位全都按原来的身体尺寸算，不会把人埋进地里。默认抬高 1.1 米（眼睛离地约 2.8 米），
数值记在 localStorage 里，下次进来还是这个高度。

想改默认值 / 范围 / 步长，改 `js/config.js` 里 `player` 的 `viewOffset`、`viewOffsetMin`、
`viewOffsetMax`、`viewOffsetStep`、`viewOffsetStepFast`。
（`player.eyeHeight` 是身体高度、碰撞用它；只想改观感请调 viewOffset，不要动 eyeHeight。）

### 学校纬度（把太阳调到你的城市）

「更多」里的第一行是**学校纬度**（滑杆 −60°~70°，或者直接选地名），它决定太阳的真实轨迹。
面板下面那行「日出 · 日落 · 昼长 · 正午高度 · 当前高度」就是按它现算的 —— 拖滑杆能立刻看到
数字变化，也能看到太阳的高低、影子长短跟着变。

默认 39.9°（北京），内置预设：漠河 52.97 / 哈尔滨 45.80 / 北京 39.90 / 西安 34.34 /
上海 31.23 / 成都 30.66 / 广州 23.13 / 香港 22.32 / 新加坡 1.35 / 伦敦 51.51 / 雷克雅未克 64.15。
想永久改成你的学校，改 `js/config.js` 里的 `world.latitude`：

```js
world: {
  latitude: 34.34,   // 例如西安
  ...
}
```

**这套数字是真的**（自检脚本会拿真实天文值核对，见第七节）：

**所有界面文字都是中英双语**：按钮、HUD、提示、题目面板、结算、设置、环境面板都是

## 六、资源流水线（想换模型 / 换图片时用）

`tools/` 里的脚本只依赖 Python 标准库 + numpy + Pillow（`pip install numpy pillow`）。
默认从 `e:\DESKTOP 20260207\CDTZ`（原来的原型目录）读取素材，可以用参数改。

```bat
:: 1) OBJ → GLB：60.3 MB 变 16.9 MB，生成 city_manifest.json，
::    并把 y<0 的地下部分单独切成 district_00_underground.glb
python tools\obj2glb.py --src "e:\DESKTOP 20260207\CDTZ" --out assets\models
python tools\obj2glb.py --split-y 0        :: 默认值；传 1e9 就完全不切分

:: 2) 分析这 6 个模型的关系 → assets\models\tile_relationships.json
::    （谁是最新那一版、哪些只是它的早期版本）
python tools\analyze_tiles.py --voxel 2

:: 3) 图片压缩 + 生成 favicon
python tools\optimize_images.py --src "e:\DESKTOP 20260207\CDTZ"

:: 4) 独立校验生成的 GLB（容器、访问器、索引范围、与源 OBJ 的顶点集合比对、
::    以及“地下部分是否真的完全埋在地面之下”）
python tools\verify_assets.py

:: 5) 需要重新下载 three.js 时
python tools\fetch_vendor.py --force
```

`obj2glb.py` 做的事：处理 Rhino 写出来的 `\` 折行、把 3~8 边形扇形三角化、
按材质拆 primitive、把 MTL 的 `Kd/d/Ns` 转成 PBR 参数、丢掉没有用的 UV、
**按三角形三个顶点的高度把几何切成地上 / 地下两份**。

`analyze_tiles.py` 做的事：把每个模型的顶点丢进体素网格，比较彼此的空间占用，
输出三层（地下/地面/楼上）的顶点分布、两两重合率矩阵，以及给游戏用的
`roles`（`newest` / `draft` / `alternative` / `additional`）。

每个脚本都会写一份 `*_report.txt`，可以直接看到前后体积与校验结果
（`obj2glb_report.txt`、`tile_report.txt`、`verify_assets_report.txt`…）。

## 七、自检（改完代码之后建议跑一次）

```bat
python tools\smoke.py
```

它会用 Edge / Chrome 的无头模式打开 `tests/smoke.html`，真实地：

* 载入 6 个 GLB，核对三角形 / 顶点 / 包围盒与清单是否一致
* 拼城市，检查地块不重叠、地面存在
* 为 49 万面建 BVH，测射线性能（本机约 0.04 ms/次）
* 模拟玩家下落 + 按住 W 走 600 帧，检查贴地、不穿墙、不掉出地图
* 模拟 6 只敌人巡逻 300 帧，检查都不悬空、不掉下去
* 验证判题的大小写 / 标点 / 繁简体 / 数学等价

结果写进 `smoke_report.txt`，最后一行是 `RESULT ok` 或 `RESULT fail —— N 项失败`。

另外还有一个**端到端**测试，它会在同源 iframe 里真正打开游戏本体，点“开始游戏”，
走到敌人面前、答对、答错、重开、把 6 只全部击败、看结算、再回到标题：

```bat
python tools\smoke.py --page tests/e2e.html      :: 报告写进 e2e_report.txt
```

> 注意：无头浏览器用的是软件渲染（SwiftShader），一帧要几百毫秒，
> 所以自检里所有“等一下”的判断都写成了轮询等待，不要改成固定 `sleep`。

### 画面检查：给每种天气出一张"明信片"

因为光照这种东西光看代码看不出问题，所以有一个专门的工具：它会让游戏定格在指定的
季节/天气/时间上，把那一帧导出成 PNG，再用 Pillow **量化亮度**（整体/天空/地面、
过曝像素比例、全黑像素比例）：

```bat
python tools\postcard.py                        :: 默认拍 6 个典型场景
python tools\postcard.py --eye                  :: 用人视角（出生点的高度）
python tools\postcard.py --preset winter,snow,20,冬夜雪   :: 自己指定：季节,天气,小时,说明
```

结果在 `postcard_report.txt` 里，截图放在 `tools/postcard/`。判定标准是
「过曝像素 > 35% 且整体很亮」= 偏亮，「整体 < 6% 且全黑 > 50%」= 偏暗。
调曝光就改 `js/config.js` 里的 `world.exposure.day / .night`。

> 顺带说明：无头环境里 `__wallcity.probeRender()`（直接读像素的探针）常常读回 0，
> 所以端到端测试遇到这种情况会跳过亮度判定 —— 这也是为什么要用上面这个"导出 PNG 再分析"
> 的办法，它不依赖浏览器的像素回读能力。

## 八、常见问题

**Q：双击 `index.html` 一片空白 / 控制台报 CORS。**
必须走本地服务器（见第一节），`file://` 下浏览器不允许加载 ES Module。

**Q：双击了 `启动游戏.bat`，但浏览器里还是白屏 / 不知道服务器起来没有。**
跑一下诊断脚本，它会自己起一个临时服务器，把游戏需要的 14 个文件全部请求一遍：

```bat
python tools\check_http.py
python tools\check_http.py --url http://127.0.0.1:8080   :: 检查已经在跑的那个
```

正常的话每一项都是 `200` 和正确的 MIME 类型（`.glb` 是 `model/gltf-binary`），
最后一行会告诉你该用哪个地址打开。结果同时写进 `check_http_report.txt`。

**Q：黑色窗口一闪就没了。**
说明这台机器上没有 Python（或者安装时没勾 “Add Python to PATH”）。
装一个 Python 3 就行；或者在 VS Code 里用 Live Server 插件打开 `index.html`，
效果完全一样。

**Q：想换端口 / 8080 被占用了。**
`python tools\serve.py --port 9000`；不加参数时端口被占用会自动往后找（8081、8082…）。

**Q：怎么让别人也能玩？**
这个游戏没有任何后端，把整个 `E:\WallCity` 文件夹原样上传到任意静态托管
（GitHub Pages、Netlify、对象存储、自己的 Nginx / 宝塔站点）就能直接跑。
上线时把 `tools/serve.py` 里那句 `Cache-Control: no-store` 去掉或改成 `public, max-age=…`，
17 MB 的模型就能被浏览器缓存住，第二次打开会快很多。

**Q：点了“开始游戏”鼠标没有锁定。**
浏览器的指针锁定需要一次真实点击，且要页面处于前台。如果浏览器弹了权限提示，
允许即可。触屏设备没有指针锁定，这个玩法基本只适合桌面端。

**Q：载入很慢。**
第一次要下载 16.9 MB 的模型并解析，之后再打开会命中浏览器 HTTP 缓存（本项目的
`serve.py` 为了开发方便关掉了缓存，正式部署可以打开 `Cache-Control`）。
载入完还会建 BVH（本机约 0.3–0.5 秒）。进度条会逐项显示在做什么。

**Q：卡顿怎么办？**
设置里把画质调到“流畅”（关阴影 + 降低渲染分辨率），另外把浏览器窗口调小一些。
三档画质分别控制：像素比、阴影开关、阴影贴图分辨率。

**Q：想改题目。**
`js/questions.js`：`CHINESE_BANK` / `ENGLISH_BANK` 是固定题库，数组里加一条
`{ q: '题干', a: ['可接受答案1', '答案2'], hint: '提示' }` 即可；
数学题在 `MATH_MAKERS` 里，每个函数返回一道题，注意答案必须是数字。

**Q：想改怪物长什么样 / 惩罚图片文案。**
`js/config.js` 里的 `SUBJECTS`：颜色、脸部贴图路径、惩罚图片数组、惩罚文案都在这里。
如果发现怪物的脸朝向不对，把 `CONFIG.enemies.faceYawOffset` 改成 `Math.PI`。

**Q：想换模型。**
把新模型导出成 OBJ（Y 轴朝上、水平面当地面）**直接放进 `assets/models/`**，
然后按顺序跑（两个脚本现在的默认源目录就是 `assets/models`，不用再加 `--src`）：

```bat
python tools\obj2glb.py        :: OBJ → GLB，顺便重写 city_manifest.json
python tools\analyze_tiles.py  :: 重新判断“哪一版是最新的”→ tile_relationships.json
python tools\verify_assets.py  :: 对照清单验证 GLB
```

* 贴图：`.mtl` 里 `map_Kd` 引用的图片会被**打包进 GLB**（保留 UV），所以整个文件夹
  拷走仍然能离线跑；某张图不在磁盘上时，那个材质会退回用 `Kd` 颜色，并在清单的
  `missingTextures` 里列出来（例如 2026-09 这版缺 `Terracotta_200_DB50.jpg`）。
* 多块模型的世界坐标要一致（它们按原始坐标拼在一起）；互不重叠的会被判成
  `additional` 并全部显示。
* 换完模型记得看一眼**出生点**：`js/config.js` 的 `spawn.pinned` 把出生点钉死成
  一个世界坐标（当前 `[20, 2.15, -43]`），换模型后如果那个位置变成墙里/悬空，
  游戏会给出 `console.warn` 并自动回退到“从校园中心往外找”，这时把新的坐标填回去即可。

**Q：为什么只看到一版校园？我明明做了 6 个模型。**
因为分析下来它们是同一座校园的 6 次导出（详见第三节）。想全部看到：
把 `js/config.js` 里的 `world.includeDrafts` 改成 `true`。

**Q：怎么换季节、天气、时间？**
右侧的「环境 Environment」栏就是（标题界面一直显示，游戏里按 <kbd>H</kbd> 开关）：
三个下拉框分别是季节、天气、时间，下面还有个 0~24 点的滑杆可以微调。想快速换就按
<kbd>F</kbd>（换天气）、<kbd>1</kbd>~<kbd>4</kbd>（换季节）、<kbd>[</kbd> <kbd>]</kbd>（调时间）。
选择会记住，下次打开还是这套。

**Q：下雨下雪会影响玩法吗？**
只影响画面：光照变暗、能见度变短（雨 260 米、雾 110 米）、地面变湿反光。
移动速度、敌人行为、答题都不受天气影响。夜里窗户会亮起来，方便你认路。

**Q：画面偏亮 / 偏暗 / 天空太白？**
改 `js/config.js` 里的 `world.exposure.day`（白天，默认 0.8）和 `world.exposure.night`
（夜里，默认 0.42）：调小变暗。天空太白就把天气调到"阴天/雾"，或者把
`world.sunIntensity`（默认 4.2）调小。

**Q：帧率还是不够高？**
设置里把画质调到"流畅"；游戏本身还有自适应分辨率（帧率长期低于 38 会自动降到 60-85%）。
想关掉就改 `js/config.js` 里的 `performance.autoScale = false`。

**Q：我在楼里/屋顶上，怪物却在楼下，答不了题？**
这是故意的：答题要水平 3 米以内、高度差 12 米以内。靠近时 HUD 会提示“楼上/楼下 N 米”，
按小地图找路下去就行。卡住了按 `R` 回到出生点。

**Q：想让它更简单 / 更难。**
`js/config.js`：`enemies.perSubject`（每学科几只）、`enemies.chaseSpeed`、
`enemies.triggerRadius`（触发答题的距离）、`player.walkSpeed`、`quiz.mathLevelStep`。

## 十、出生方式：空降

开局不是“站在地面上生”，而是**从校园最高点上方 45 米跳伞落下来**：

* 起始高度 = 校园最高点 + `spawn.skydiveClearance`（45 米），下落速度被 `spawn.skydiveMaxFall`
  （26 米/秒）拉住 —— 落点看得清、也来得及用 WASD 微调（`spawn.skydiveAirControl` 0.85）。
* 默认落点 XZ 仍然是 `spawn.pinned`（当前 `[20, 2.15, -43]`）；空降模式下它只是个“往哪儿落”的
  参考，落在哪一层由伞降过程决定。**落地后那个位置就成为新的出生点**（按 <kbd>R</kbd> 回这里），
  所以也不怕换模型以后钉住的坐标正好在墙里/地下室里。
* 想改回“直接站在地面上生”：把 `js/config.js` 的 `spawn.skydive` 设成 `false`。
* 老师（怪物）只会被放在**露天**的地方：采样巡逻点/出生点时要求“从天上往下看能直接看到这个面，
  而且头顶 2.2 米内没有东西”，所以它们不会出现在封闭房间或地下空间里。

## 九、已知限制


* 同一座校园如果导出过多版，默认只显示最新那一版（现在是 `district_01`），早期版本要么
  被隐藏（`includeDrafts`），要么只保留地下部分 —— 因为它们是同一座校园的不同版本，同时摆出来会互相穿插。
* 怪物走的是“随机巡逻点 + 射线探路”，不是真正的 NavMesh：偶尔会贴着墙走几步，
  但被挡住时会左右试探着绕路（`enemies.dodgeAngles`），四面都过不去才换目标点。
* 它们**不在一个平面上活动**：巡逻点以“高度带”（`enemies.bandHeight`，默认 ±14 米）
  围绕一个参考高度采样 —— 平时参考自己脚下那一层，你走近（`roamRadius × 1.5` 以内）
  时参考**你所在的高度**，所以你在三楼，它们会顺着楼梯/坡道找上来；
  台阶、缓坡、平台靠 `enemies.climbHeight`（默认 2.6 米）迈上去。
  没有楼梯通到的地方（比如孤立的屋顶）它们也上不去 —— 和你一样。
  出生时的高度范围是 `enemies.spawnBandHeight`（默认 ±22 米），所以它们会散在校园各层。
* 你能走到的楼层取决于模型本身的楼梯/坡道：模型里没有连通的地方就走不过去。
  如果卡在某处，按 `R` 可以回到出生点。
* 地下部分（`y < 0`）是保留着的，但校园本体里如果没有通向下层的楼梯，你就下不去。
* 校园里没有车辆、NPC、路灯之类的点缀，就是纯粹的校园本体。
* 夜里的亮度比现实高不少（游戏性考虑，不然看不见路），而且 three 的物理天空着色器没有
  真正的"夜天顶"项，所以天空靠压低 rayleigh + 降曝光来变暗，不是天文学意义上的夜空。
* 雨雪只是视觉粒子，不会积水、不会积雪成堆（冬天+下雪会让地面和墙面整体变浅）。
* 没有存档，通关数据只在当次会话里；也没有移动端操控方案（需要键盘 + 鼠标）。
* 三张“惩罚图片”是按原文件名猜的用途（`cheat1/cheat2` 给了数学和英语、
  `book1/book2` 给了语文），如果对不上，改 `js/config.js` 里的 `images` 数组即可。
